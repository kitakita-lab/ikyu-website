# Harness V0 — 変更作業の手順

目的：人間（こーたろー）を AI 間の情報運搬から外し、最後の意思決定者にする。品質は今と同じ水準を保つ。

- 実装・進行管理：Claude Code
- 独立コードレビュー：Codex（GitHub の PR 上）
- ブランド・保留事項・ルール追加・マージ：人間

## 手順

1. **ルールを読む**：`AGENTS.md` とこのファイル。
2. **受け入れ条件を確定する**：依頼文に書かれた受け入れ条件を、原文のまま PR 本文に転記する。依頼に無い場合は、作業前に人間へ確認する（Claude が自分で作って採点しない）。
3. **実装する**：依頼の範囲だけを変更する。
4. **機械チェック**：`npm run verify`（lint・型チェック・テスト・ビルド・サイト検査。中身は `docs/brand-review.md` の「1.」）。失敗したら直してから先へ進む。テストや検査の条件を緩めて通すことはしない。
5. **PR を作る**：本文は `.github/pull_request_template.md` の型に従う。PR を作ったら、最新 commit の CI（`Quality Checks`）と `Cloudflare Pages` が成功したことを確認する。失敗したら原因を直して push し直す（手順4の「2回直しても通らない」に数える）。
6. **Codex レビューを依頼する**：PR に `@codex review` とだけコメントする。補足の説明・観点・Claude の要約は書かない（レビューの独立性を保つため）。PR 本文やその他のコメントには `@codex` と書かない（「Codex レビュー」と書く）。`@codex` を含む文は、レビューではなく Codex への作業依頼として扱われることがある。
7. **Codex の回答を待って取得する**：`chatgpt-codex-connector[bot]` によるレビュー（`pulls/{番号}/reviews`）、行コメント（`pulls/{番号}/comments`）、通常コメント（`issues/{番号}/comments`）のうち、手順6の後に付いたものを取得する。
   - Codex の返答にある「Reviewed commit」が PR の最新 commit と一致していることを確かめる。古い commit へのレビューは、最新の変更をレビューした結果として扱わない。
   - 確認は **60秒ごと**、待つのは **最大10分** まで（過去の実績では依頼から2〜3分で返答）。
   - 10分で取得できなければ STOP し、「Codex 応答待ちで STOP した」と報告する。依頼の再投稿や別のレビュー手段での代替はしない。
8. **指摘を仕分ける**：すべての指摘を「採用・却下・保留」に分け、理由を付けて PR にコメントする。
   - 採用：正誤がはっきりしており、依頼の範囲内で直せるもの
   - 却下：誤り、または依頼の範囲外・好みの問題と判断したもの（理由を必ず書く）
   - 保留：見た目・文言・ブランドに関わるもの、判断が分かれるもの → 人間に渡す
9. **採用分だけ直す** → 手順4の機械チェックをやり直す。
10. **2回目のレビュー**：手順9で修正した場合だけ、もう一度 `@codex review` とコメントし、手順7〜8を行う。**レビューは最大2回**。2回目で残った指摘はすべて「保留」にする。
11. **STOP**：PR 本文を最終化し、人間に報告して止まる。マージはしない。

## 止まる条件（回避策を作らない）

次のいずれかが起きたら、その時点で作業を止め、人間に報告する。別の方法で無理に回避しない。

- Codex の回答を待てない、または10分以内に取得できない
- Codex がレビュー以外の返答をした（例：環境の作成を求める案内）
- 同じセッションで処理を続けられない
- 2回目の `@codex review` を依頼できない
- 機械チェックが2回直しても通らない
- 判断が見た目・文言・ブランドに及び、作業を続ける前提が変わる

報告では「どこまで自動でできたか」「どこで人間が必要になったか」を書く。

## PR 本文の型

`.github/pull_request_template.md` を使う（GitHub の画面で PR を作るときも同じ型が入る）。
見た目・文章・写真・購入導線に触れる PR では、テンプレートの「ブランド確認（人が判断）」を人に渡す。観点は `docs/brand-review.md`。

## ルールの追加

- Claude は `AGENTS.md` を自分で変更しない。追加候補は PR 本文に書くだけにする。
- 人間が「追加して」と明示した場合だけ、別途 `AGENTS.md` に反映する。

## 記録（人間）

マージ時に PR へ1行コメントする：`中継 n／差戻 n`

- 中継：AI 間でコピペした回数
- 差戻：マージ前後に人間が見つけて直させた件数

## GitHub の設定（人間が行う・未適用の推奨）

`main` を守る Ruleset の推奨値。設定は GitHub の Settings → Rules → Rulesets で人間が行う（Claude は変更しない）。

| 項目 | 推奨 |
|---|---|
| 対象 | `main`（Default branch） |
| PR 必須 | あり。承認数 0（1人運用のため。共同編集者を増やしたら 1 にする） |
| 必須チェック | `Quality Checks`（GitHub Actions）と `Cloudflare Pages`（Cloudflare Workers and Pages） |
| マージ方式 | Merge commit のみ（これまでの履歴と同じ） |
| Bypass | なし |
| force push・ブランチ削除 | 禁止 |

Vercel のチェックは必須にしない（本番は Cloudflare Pages。Vercel 連携は移行期の名残）。
